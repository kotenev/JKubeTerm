## Practices

### :warning: Never reuse a PV across namespaces without full wipe {#pv-cross-ns-reuse}

**ID:** `pv-cross-ns-reuse` · **Severity:** WARN · **Applies to:** PersistentVolume

**Why it matters.** Rebinding a Released PV to a new namespace without scrubbing leaks the previous tenant's data to the next claimant — a silent cross-tenant breach.

**Fix in JKubeTerm.** Wipe (or destroy and reprovision) between tenants; treat Released PVs as tainted until scrubbed and logged; prefer dynamic provisioning over manual rebinding.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/persistent-volumes/)

### :warning: Treat local volumes as cattle with node affinity, not pets {#pv-local-volumes}

**ID:** `pv-local-volumes` · **Severity:** WARN · **Applies to:** PersistentVolume

**Why it matters.** Local PVs die with their node, yet teams use them for "fast prod DBs" without replication, turning every node failure into permanent data loss.

**Fix in JKubeTerm.** Use local volumes only with nodeAffinity plus app-level replication (or ephemeral scratch); document single-node fate explicitly; prefer CSI for anything irreplaceable.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/volumes/#local)

### :warning: Alert on fill rate, not just fill percentage {#pv-monitoring-fill-rate}

**ID:** `pv-monitoring-fill-rate` · **Severity:** WARN · **Applies to:** PersistentVolume

**Why it matters.** A volume at 60% filling 10% per hour dies before morning; static 85% alerts fire too late for fast growers and too early (noise) for slow ones.

**Fix in JKubeTerm.** Alert on predicted exhaustion (linear forecast under N days) per volume class; pair with growth-rate dashboards per namespace.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/persistent-volumes/)

### :warning: Mount NFS with hard, intr and timeouts tuned {#pv-nfs-hard-mounts}

**ID:** `pv-nfs-hard-mounts` · **Severity:** WARN · **Applies to:** PersistentVolume

**Why it matters.** Soft NFS mounts with short timeouts return I/O errors to apps on transient blips, corrupting writes that hard mounts would have retried transparently.

**Fix in JKubeTerm.** Use hard mounts with tuned timeo/retrans for stateful NFS; soft only for best-effort caches with app-level retry. Test server-failure behavior, not just happy path.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/volumes/#nfs)

### :warning: Snapshot PVs before storage upgrades and migrations {#pv-snapshot-before-upgrade}

**ID:** `pv-snapshot-before-upgrade` · **Severity:** WARN · **Applies to:** PersistentVolume

**Why it matters.** CSI driver upgrades and StorageClass migrations corrupt or orphan volumes rarely but catastrophically, with no undo except a pre-change snapshot.

**Fix in JKubeTerm.** Snapshot every production PV before driver, Kubernetes or class changes; verify snapshot ReadyToUse; keep until the new stack proves stable for a week.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/volume-snapshots/)

### :information_source: Use ReadWriteOncePod for strict single-Pod writers {#pv-access-readwriteoncepod}

**ID:** `pv-access-readwriteoncepod` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Classic RWO still allows two Pods on the same node to race a volume during rolling handovers, corrupting writers that assume exclusivity.

**Fix in JKubeTerm.** On supported drivers use ReadWriteOncePod for singleton writers (migrations, singletons); verify driver support before relying on it in prod.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/persistent-volumes/#access-modes)

### :information_source: Verify actual usable capacity, not just requested {#pv-capacity-actual}

**ID:** `pv-capacity-actual` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Filesystem overhead, thin-provisioning and driver reservations mean a "100Gi" volume offers less, and apps crash on ENOSPC while dashboards show free space.

**Fix in JKubeTerm.** Measure usable bytes inside Pods after provisioning (df vs request); record overhead per driver; size requests to usable, not nominal, capacity.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/persistent-volumes/)

### :information_source: Place Ceph pools per performance tier {#pv-ceph-pool-placement}

**ID:** `pv-ceph-pool-placement` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Single-pool Ceph mixes DB WAL with backups, letting bulk I/O starve latency-sensitive volumes.

**Fix in JKubeTerm.** Separate pools (replicated SSD vs erasure HDD); map StorageClasses per pool with docs.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/volumes/#rbd)

### :information_source: Enable CSI capacity reporting for smarter scheduling {#pv-csi-capacity-reporting}

**ID:** `pv-csi-capacity-reporting` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Without CSIStorageCapacity the scheduler places Pods needing volumes on nodes whose local topology has no capacity left.

**Fix in JKubeTerm.** Enable capacity reporting on CSI drivers; treat missing capacity objects as driver health signal.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/storage-capacity/)

### :information_source: Pin CSI driver versions with upgrade runbooks {#pv-csi-driver-pinned}

**ID:** `pv-csi-driver-pinned` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Auto-upgraded CSI drivers change mount behavior, topology handling and snapshot APIs under running volumes, breaking attaches after innocent-looking upgrades.

**Fix in JKubeTerm.** Pin driver versions in Git, upgrade per vendor runbook with snapshot-before-upgrade (see above), canary on non-prod pools first.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/volumes/#csi)

### :information_source: Audit Delete-retention PVs for data classes {#pv-delete-retention-audit}

**ID:** `pv-delete-retention-audit` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Delete policy on data-class PVs wipes on routine namespace cleanup.

**Fix in JKubeTerm.** Restrict Delete to scratch classes via policy; require Retain for data classes.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/persistent-volumes/#reclaiming)

### :information_source: Document every StorageClass as a product contract {#pv-documentation-per-class}

**ID:** `pv-documentation-per-class` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Undocumented classes force teams to guess performance, encryption, backup and topology behavior per volume, repeating the research every incident.

**Fix in JKubeTerm.** Publish per-class cards: provisioner, performance, encryption, backup policy, topology, expansion behavior, reclaim default. Link from JKubeTerm via class annotations.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/storage-classes/)

### :information_source: Enable CSI capacity reporting for smarter scheduling {#pv-driver-capacity-reporting}

**ID:** `pv-driver-capacity-reporting` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Without CSIStorageCapacity the scheduler places Pods needing volumes on nodes whose local topology has no capacity left, causing late Pending after scheduling looked fine.

**Fix in JKubeTerm.** Enable capacity reporting on CSI drivers; verify CSIStorageCapacity objects per topology segment; treat missing capacity objects as a driver health signal.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/storage-capacity/)

### :information_source: Match EBS-style volumes to workload AZs {#pv-ebs-az-affinity}

**ID:** `pv-ebs-az-affinity` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Cross-AZ attach fails or bills egress per I/O for zonal volumes.

**Fix in JKubeTerm.** Constrain both PV topology and Pod affinity to the same zone; verify attach latency.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/volumes/#awselasticblockstore)

### :information_source: Encrypt cloud volumes with customer KMS keys {#pv-ebs-encryption-kms}

**ID:** `pv-ebs-encryption-kms` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Default SSE still leaves key control with the provider; compliance needs CMKs.

**Fix in JKubeTerm.** Set encrypted plus kmsKeyId per sensitive StorageClass; verify per-PV encryption.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/storage-classes/)

### :information_source: Duplicate KMS encryption guard for sensitive PVs {#pv-ebs-encryption-kms-dup}

**ID:** `pv-ebs-encryption-kms-dup` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** A second explicit check keeps encryption policy visible in the advisor backfill.

**Fix in JKubeTerm.** Keep encrypted StorageClasses for sensitive namespaces; verify per-PV encryption.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/storage-classes/)

### :information_source: Choose ephemeral volumes for scratch, PVs for state {#pv-ephemeral-vs-persistent}

**ID:** `pv-ephemeral-vs-persistent` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Scratch data on PVs wastes provisioned capacity, snapshot budgets and backup windows; state on emptyDir evaporates on reschedule with no recovery.

**Fix in JKubeTerm.** Use emptyDir or generic ephemeral volumes for caches and scratch; reserve PVs for data that must survive Pod rescheduling. Review volume types quarterly.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/ephemeral-volumes/)

### :information_source: Grow filesystems manually when drivers don't {#pv-fs-resize-manual}

**ID:** `pv-fs-resize-manual` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Some drivers expand the block device but not the filesystem, so Pods see the old size despite the PVC showing grown — confusion blamed on Kubernetes.

**Fix in JKubeTerm.** After expansion verify inside the Pod (df); run filesystem resize (or restart for online-capable drivers) per driver docs; record per-class behavior in the runbook.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/persistent-volumes/#expanding-persistent-volumes-claims)

### :information_source: Isolate noisy I/O neighbors per disk class {#pv-io-isolation}

**ID:** `pv-io-isolation` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Sharing one disk (or one cloud volume type) between etcd, databases and log scrapers makes tail latency everyone's problem with no per-tenant accounting.

**Fix in JKubeTerm.** Separate latency-sensitive (etcd, DB WAL) from bulk (logs, backups) onto different PVs/classes/disks; monitor per-volume latency, not node averages.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/persistent-volumes/)

### :information_source: Set Longhorn replica counts per criticality {#pv-longhorn-replica-count}

**ID:** `pv-longhorn-replica-count` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Single-replica Longhorn volumes die with their node despite looking persistent.

**Fix in JKubeTerm.** Set 3 replicas for prod data, 2 minimum; alert on degraded replica counts.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/volumes/)

### :information_source: Set mountPropagation only where container runtimes need it {#pv-mount-propagation}

**ID:** `pv-mount-propagation` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Bidirectional propagation lets containers mount onto the host, escaping containment via mount namespace manipulation — rarely needed outside CSI and runtime agents.

**Fix in JKubeTerm.** Default to None; use HostToContainer for log readers, Bidirectional only for CSI drivers that document the requirement; review every bidirectional mount quarterly.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/volumes/)

### :information_source: Keep NFS idmapping coherent across nodes {#pv-nfs-idmap-coherence}

**ID:** `pv-nfs-idmap-coherence` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Squashed or mismatched UID mapping turns correct PVC mounts into permission-denied per node.

**Fix in JKubeTerm.** Standardize idmapd.conf plus fsGroup policy; test mounts from every pool.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/volumes/#nfs)

### :information_source: Reclaim Released PVs deliberately, never by accident {#pv-orphan-reclaim}

**ID:** `pv-orphan-reclaim` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Released PVs pile up holding data nobody owns (billing, confusion) or get manually recycled with stale data attached to new claims (leak across tenants).

**Fix in JKubeTerm.** Triage Released PVs monthly: scrub-and-reuse for scratch (documented wipe), retain-and-archive for valuable, delete only after backup verification.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/persistent-volumes/#reclaiming)

### :information_source: Prewarm EBS-style volumes before production cutover {#pv-prewarm-performance}

**ID:** `pv-prewarm-performance` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Fresh cloud volumes deliver a fraction of rated IOPS until initialized, so fresh restores and new DBs perform terribly exactly during the critical cutover window.

**Fix in JKubeTerm.** Prewarm (fio read pass or vendor tooling) after restores and fresh provisioning; benchmark before cutover, not after complaints.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/persistent-volumes/)

### :information_source: Respect cloud volume count and size limits per node {#pv-quota-driver-limits}

**ID:** `pv-quota-driver-limits` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Cloud attach limits (e.g. 39 EBS per node) turn dense Pods Pending with opaque attach errors once the count, not capacity, is exhausted.

**Fix in JKubeTerm.** Know per-cloud per-node limits; spread Pods across nodes or use fewer larger volumes; alert on attach-limit proximity, not just byte usage.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/storage-limits/)

### :information_source: Choose the reclaim policy deliberately (alias) {#pv-reclaim}

**ID:** `pv-reclaim` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Compatibility alias for the ClusterAdvisor trigger `pv-reclaim`; canonical guidance lives in `pv-reclaim-policy` in this wiki.

**Fix in JKubeTerm.** See `pv-reclaim-policy` above for the full JKubeTerm workflow.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/persistent-volumes/#reclaiming)

### :information_source: Set SELinux mount options for shared volumes on enforcing nodes {#pv-selinux-labels}

**ID:** `pv-selinux-labels` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** On SELinux-enforcing nodes, Pods hit permission denied on correctly-provisioned volumes because labels don't allow container_t writes — misdiagnosed as storage bugs.

**Fix in JKubeTerm.** Set seLinuxOptions per StorageClass or Pod securityContext (type container_file_t or narrower); verify mounts on enforcing nodes in CI, not just permissive dev.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/volumes/)

### :information_source: Pin volumes to zones matching their consumers {#pv-topology-zones}

**ID:** `pv-topology-zones` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Zone-unaware static PVs attach-fail when Pods schedule elsewhere, or silently incur cross-zone I/O costs and latency on every operation.

**Fix in JKubeTerm.** Set nodeAffinity zones on static PVs matching workload topology; prefer dynamic provisioning with allowedTopologies over hand-placed PVs.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/storage-classes/#allowed-topologies)

### :information_source: Use VolumeAttributesClass for tunable IOPS on modern clusters {#pv-volumeattributesclass}

**ID:** `pv-volumeattributesclass` · **Severity:** INFO · **Applies to:** PersistentVolume

**Why it matters.** Recreating volumes to change IOPS tiers means data migration downtime for what should be a parameter tweak.

**Fix in JKubeTerm.** On 1.31+ clusters define VolumeAttributesClasses per tier and switch PVCs between them without recreation; verify driver support first.

**Official docs:** [kubernetes.io](https://kubernetes.io/docs/concepts/storage/volume-attributes-classes/)
